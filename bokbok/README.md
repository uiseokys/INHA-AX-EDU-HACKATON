## 실행

Python 3.10 이상이 필요합니다.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload     # http://localhost:8000
```

```bash
pytest                            # 분석·포인트·챗봇 로직 + 화면 흐름 테스트
python scripts/generate_data.py   # 합성 감정 기록 다시 만들기
./scripts/build_css.sh            # 화면의 Tailwind 클래스를 바꿨을 때만 (Node.js 필요)
```

- 날짜를 고정해 시연하려면 `BOKBOK_TODAY=2026-11-14 uvicorn app.main:app` 처럼 실행합니다.
- 화면 아래 **시연 데이터 초기화** 버튼(또는 `var/state.json` 삭제)으로 처음 상태로 돌아갑니다.
- 감정 기록에 강도(`intensity`)가 저장되기 시작한 뒤 그 이전 버전의 코드로 되돌리면 학생 화면이 열리지 않습니다. 되돌릴 때는 시연 데이터를 초기화하세요.

## 공개 테스트 사이트 (Render)

다른 팀이 체험할 수 있도록 [Render](https://render.com) 무료 요금제에 올릴 수 있게 설정해 두었습니다 (저장소 맨 위 `render.yaml`).

1. Render에 GitHub 계정으로 로그인 → **New → Blueprint** → 이 저장소 선택 → **Deploy Blueprint**
2. 몇 분 뒤 `https://<서비스 이름>.onrender.com` 주소가 생깁니다.

- `BOKBOK_MULTI=1`: **방문자(브라우저)마다 따로 체험 공간**이 만들어져서, 다른 팀이 한 일과 섞이지 않습니다. 체험 공간은 3일 뒤, 또는 서버가 다시 시작되면 지워집니다.
- `TZ=Asia/Seoul`: 오늘 날짜와 시간을 한국 기준으로 계산합니다.
- 무료 요금제는 한동안 접속이 없으면 잠들었다가, 다음 접속 때 1분 정도 걸려 깨어납니다.
- 공개 서버에는 로컬 LLM이 없으므로 복복이는 기본으로 규칙 기반으로 대답합니다. 내 컴퓨터의 로컬 LLM을 연결하려면 아래를 따릅니다.
- 다른 서비스에 올릴 때는 `Dockerfile`을 쓰면 됩니다.

### 공개 사이트에서 내 컴퓨터의 로컬 LLM 쓰기

공개 사이트(Render)의 복복이가 **내 컴퓨터에서 돌고 있는 oMLX**로 대답하게 할 수 있습니다. 시연하는 동안만 켜 두는 임시 연결입니다.

1. 내 컴퓨터에서 oMLX를 켜고, 터널 도구를 한 번 설치합니다: `brew install cloudflared`
2. `./scripts/share_local_llm.sh` 를 실행하면 `https://<임의의-이름>.trycloudflare.com` 주소가 나옵니다. 이 창은 켜 둡니다.
3. Render 대시보드 → bokbok 서비스 → **Environment** 에 세 값을 넣고 저장합니다 (저장하면 다시 배포됩니다).

| 환경변수 | 값 |
| --- | --- |
| `BOKBOK_LLM_URL` | 2번의 주소 뒤에 `/v1` 을 붙인 값 |
| `BOKBOK_LLM_MODEL` | `Qwen3-Next-80B-A3B-Instruct-oQ4` (oMLX에 올려 둔 모델 이름) |
| `BOKBOK_LLM_API_KEY` | oMLX의 API 키. **저장소·채팅에 적지 말고 Render 화면에 직접 넣습니다** |
| `BOKBOK_LLM_TIMEOUT` | `60` |

4. 공개 사이트의 복복이 대화 화면 머리말이 ‘로컬 AI 연결됨’으로 바뀌면 연결된 것입니다.

- 주소는 스크립트를 실행할 때마다 바뀝니다. 다시 실행했다면 `BOKBOK_LLM_URL` 을 새 주소로 바꿔야 합니다.
- 내 컴퓨터가 잠들거나 스크립트가 꺼지면 공개 사이트의 복복이는 규칙 기반 대답으로 돌아갑니다.
- 한동안 쓰지 않은 모델은 oMLX가 메모리에서 내려 두기 때문에, 쉬었다가 처음 보내는 말에는 대답이 40초쯤 걸릴 수 있습니다 (그다음부터는 1초 안팎). 시연 직전에 한마디 보내 미리 깨워 두세요. 그래서 `BOKBOK_LLM_TIMEOUT` 은 60초로 둡니다.
- 주소를 아는 사람은 누구나 내 컴퓨터의 oMLX에 요청을 보낼 수 있고, oMLX의 API 키가 유일한 잠금입니다. 시연이 끝나면 스크립트를 끄세요.
- 공개 사이트 방문자가 복복이에게 한 말이 내 컴퓨터로 전해져 처리됩니다. ‘로컬 LLM이라 대화가 학교 밖으로 나가지 않는다’는 설명은 이 연결 방식에는 해당하지 않습니다.

## 챗봇 '복복이'와 로컬 LLM

복복이는 **OpenAI 호환 Chat Completions API**를 제공하는 로컬 서버(Ollama, LM Studio, llama.cpp server, vLLM 등)에 연결할 수 있습니다.
모델은 정해 두지 않았고, 환경변수로 지정합니다.

| 환경변수 | 뜻 | 기본값 |
| --- | --- | --- |
| `BOKBOK_LLM_MODEL` | 사용할 모델 이름. **비어 있으면 LLM 없이 규칙 기반으로 대답** | 없음 |
| `BOKBOK_LLM_URL` | 서버 주소 | `http://localhost:11434/v1` (Ollama) |
| `BOKBOK_LLM_API_KEY` | 서버가 요구할 때만 | 없음 |
| `BOKBOK_LLM_TIMEOUT` | 응답 대기 시간(초) | `40` |

```bash
BOKBOK_LLM_MODEL=<받아 둔 모델 이름> uvicorn app.main:app --reload
```

**oMLX로 시연할 때** (팀 시연 기준 모델: `Qwen3-Next-80B-A3B-Instruct-oQ4`)

```bash
./scripts/run_local_llm.sh        # http://localhost:8020 (oMLX가 8000번을 쓰므로 8020번으로 띄움)
./scripts/run_local_llm.sh try    # 서버 대신 말투 시험만 실행
```

스크립트가 oMLX 주소와 모델 이름을 맞추고, API 키는 그 컴퓨터의 oMLX 설정에서 읽어 씁니다 (저장소에는 키가 없습니다).
생각 과정을 길게 쓰는 모델(Thinking 계열)은 대답이 느리고 비어 나올 수 있어 챗봇에는 맞지 않습니다.

대답 순서 (`app/chatbot.py`)
1. **안전 확인이 먼저**: 학생의 말에서 자해·자살 같은 긴급 신호 키워드(`data/signals.json`)를 찾으면 LLM에 맡기지 않고, 정해 둔 안전 안내(109·1388·112, 선생님 상담, 전문기관, “지금 안전한 곳에 있나요?”)로 대답합니다. 폭력·가정·온라인 피해가 의심되는 말에는 대화를 끊지 않고 평소처럼 대답하면서, 도움받을 곳으로 가는 링크만 조용히 붙입니다.
2. **정해진 대답**: “선생님한테 말할 거야?”처럼 대화가 누구에게 보이는지 묻는 말에는 LLM이 지어내지 않도록 정해 둔 문장(`fixed`)으로 대답합니다.
3. **로컬 LLM**: 모델이 설정돼 있으면 `data/chatbot.json`의 `system_prompt`, 말투 예시 대화(`examples`), 최근 대화를 함께 보내 대답합니다.
4. **규칙 기반**: 모델이 없거나 연결에 실패하면 키워드에 맞춰 미리 쓴 대답을 씁니다. 그래서 LLM이 꺼져 있어도 시연은 끊기지 않습니다.

**말투와 길이**: 모델을 다시 학습시키지 않고 지시문과 예시 대화로 맞춥니다.
- `system_prompt` + `examples`: 친구끼리 쓰는 반말로, 한 번에 한두 문장만 말하도록 알려 줍니다.
- `app/chatbot.py`의 `tidy()`: 그래도 길면 앞의 두 문장(최대 80자)만 남깁니다.
- 한자·일본어가 섞이거나, 존댓말을 쓰거나, 판정·진단처럼 들리는 말(`avoid`: 괴롭힘, 우울증, 약 등)을 하면 한 번 다시 묻고, 그래도 남으면 그 문장을 뺍니다.
- 말투를 고친 뒤에는 `./scripts/run_local_llm.sh try`로 23개 문장에 대한 대답과 글자 수, 걸린 시간을 확인합니다.

**날짜별 대화 기록** (`/student/chat/history`, 학생 본인만 봄)

- 대화 화면에는 오늘 대화만 보이고, 복복이도 오늘 나눈 이야기만 이어서 기억합니다. 날이 바뀌면 새 대화가 시작됩니다.
- ‘대화 기록’ 화면에서 날짜별로 **하루 요약 + 그날 대화 원문**을 다시 볼 수 있습니다. 요약은 로컬 LLM이 학생의 말만 보고 한두 문장으로 쓰고(`data/chatbot.json`의 `daily.prompt`), LLM이 없으면 “이야기를 n번 주고받았어”로 적습니다.
- 요약은 처음 볼 때 만들어 저장하고, 그날 학생이 한 말이 늘었을 때만 다시 만듭니다.
- 학생은 하루 단위로 기록을 자기 화면에서 지울 수 있습니다(원본은 보존 기록에 남습니다). 이 기록과 요약은 선생님 화면 어디에도 나오지 않습니다.
- 처음 상태에는 시연용으로 지난 이틀 치 예시 대화가 들어 있습니다 (`data/class.json`의 `seed.chats`).

**욕설·비속어** (`app/profanity.py`, `data/profanity.json`)
- 학생이 쓴 욕설은 글자 수만큼 `*`로 바꿔 저장하고 보여 줍니다 (`씨발` → `**`). 꾸짖는 말은 하지 않습니다.
- 대답을 만들고 위험 신호를 살필 때는 가리기 전의 말을 봅니다. 욕이 섞여 있어도 신호를 놓치지 않기 위해서입니다.
- 복복이의 대답에 욕설이 있으면 한 번 다시 묻고, 그래도 남아 있으면 그 문장을 뺍니다.
- 낱말 목록은 단순 비교라서 놓치거나 잘못 가릴 수 있습니다. `data/profanity.json`에서 더하고 뺍니다.

**선생님께 조용히 전하기** (`app/chatbot.py`의 `judge`, `assess`, `converse`)

학생이 가입할 때 ‘도움이 필요해 보이면 선생님께 전해진다’는 약속에 동의했다고 가정하고, 대화 중에는 학생 화면에 아무 표시도 하지 않습니다. (동의 화면은 아직 만들지 않았습니다.)

| 단계 | 기준 | 선생님 화면 |
| --- | --- | --- |
| 전하지 않음 | 일상 이야기, 한 번 속상했던 일, 공부 걱정 | 아무것도 전해지지 않음 |
| 살펴보기 | 구체적인 피해는 없지만 여러 번에 걸쳐 많이 힘들다고 함 (세 마디 이상 이어질 때만) | ‘관찰 필요’ + “살펴볼 신호가 감지되었어요” |
| 확인 필요 | 따돌림·폭력·금품 요구·가정·온라인 피해처럼 구체적인 일을 말함 | ‘상담 권장’ + “위험 신호가 감지되었어요” |
| 긴급 | 자해·자살을 떠올리게 하는 말, 당장 위험한 상황 | ‘상담 권장’ + “긴급한 위험 신호가 감지되었어요” (학생에게는 안전 안내) |

- 로컬 LLM이 학생의 최근 말(최대 8개)을 보고 단계를 판단합니다 (`data/chatbot.json`의 `judge.prompt`). 키워드에 없는 말(“나만 빼고 단톡방 만들었대”)도 흐름으로 판단합니다.
- 선생님께는 **신호가 있었다는 사실과 단계만** 전해집니다. 무슨 이야기였는지(분류, 키워드, AI 요약, 대화 원문)는 선생님 화면에 나오지 않고 알림에 저장하지도 않습니다. 같은 날의 대화 신호는 알림 하나로 묶고, 단계가 올라가면 그 알림의 단계만 올립니다.
- LLM이 없으면 키워드로 찾은 신호만 전합니다.
- 감정 기록 문장에서 찾은 신호도 같은 방식입니다. 선생님께는 “감정 기록에서 위험 신호가 감지되었어요”와 단계만 보이고, 어떤 표현이었는지는 보이지 않습니다. (학생이 문장을 공유하기로 한 경우에만 기록 목록에서 그 문장을 볼 수 있습니다.)
- 복복이는 학생에게 거짓말을 하지 않습니다. “선생님한테 말할 거야?”라고 물으면 정해 둔 문장으로 사실대로 답합니다.
- 판단 기준을 고친 뒤에는 `./scripts/run_local_llm.sh judge`로 24개 대화에 대한 판단 결과를 확인합니다.
- **단계별 대응 안내**: 신호가 있는 학생의 상세 화면에는 가장 높은 단계에 맞춰 ‘이렇게 해 주세요 / 이것은 피해 주세요’가 나옵니다(`data/signals.json`의 `response_guide`). 일반적인 안내 초안이므로 현직 교사·상담교사의 검토가 필요합니다.
채팅 화면 머리말의 표시(‘로컬 AI 연결됨’ / ‘규칙 기반 응답’)로 현재 상태를 확인할 수 있습니다.

## 시연 흐름

1. `/` → **학생으로 시작하기** → 처음 접속하면 **약속(동의)** 화면 → 학기 초 **기본 정보** 입력 (건너뛰기 가능)
2. 오늘 기록이 없으면 홈보다 먼저 **감정 휠**(`/student/record`)이 뜸 → 스티커 선택 → **강도 고리**(1~5)를 돌리고 감정 단어 선택 → 짧은 문장 → 기록하고 포인트 받기 (‘나중에 할게요’로 오늘 하루 미룰 수 있음)
3. 부정 감정을 기록하면 포인트 적립 화면에 **복복이 대화 권유**가 함께 뜸 (‘지금은 괜찮아요’로 거절 가능)
4. `/student/chat` 에서 복복이와 대화. 위험한 표현을 말하면 안전 안내가 뜨고 선생님께 알림
5. `/teacher` 상단에 **카톡 공지처럼 고정된 알림**, 학생별 확인 목록에서 ‘상담 권장’ 확인 → 학생 상세 리포트
6. `/student/counsel` 에서 선생님이 열어 둔 시간으로 **상담 신청** → `/teacher/counsel` 에서 확정
7. `/student/shop` 에서 포인트로 **상품 교환 신청** → `/teacher/shop` 에서 승인

| (3) 복복이 챗봇 | `/student/chat` | `/teacher/alerts`, 상단 고정 알림 |
| (4) 외부 상담·지원기관 연계 | `/student/help`, `/student/counsel` | `/teacher/counsel` |
| (5) 포인트·우리 반 상점 | `/student/points`, `/student/shop` | `/teacher/shop` |
| ⑥ 지속적인 사후 관리 | — | 학생 상세 › 사후 관리 |

## 약속(동의) 화면

처음 접속하면 기본 정보보다 먼저 **약속 화면**(`/student/promise`)이 나옵니다. 내 기록과 대화가 누구에게 어떻게 보이는지 알려 주고 하나씩 눌러 확인받습니다. 문구는 `data/chatbot.json`의 `promise`에 있고, 실제 동작과 다르게 쓰면 안 됩니다.

| 묶음 | 내용 | 확인하지 않으면 |
| --- | --- | --- |
| 감정을 기록할 때 (3가지) | 스티커·강도·단어는 선생님이 봄, 문장은 고른 것만 / 위험해 보이는 말은 ‘신호가 있다’는 것만 전해짐 / 원본 그대로 보존 | 시작할 수 없음 |
| 복복이와 이야기할 때 (2가지) | 대화는 선생님이 볼 수 없음 / 힘들거나 위험해 보이면 ‘신호가 있다’는 것만 전해지고 그때 따로 알려 주지 않음 | 복복이 대화만 잠기고, 감정 기록·상점은 그대로 사용 |

- 약속은 언제든 다시 보고 바꿀 수 있습니다(대화 화면의 ‘약속 다시 보기’). 무엇을 약속했는지와 바꾼 이력은 보존 기록에 남습니다.
- 실제 학교에서는 이 화면과 별도로 학기 초에 학생·보호자 동의서를 받아야 합니다. 화면에도 그렇게 적어 두었습니다.

## 기록의 무결성과 위변조 방지

화면에 보이는 상태(`var/state.json`)와 별도로, 기록이 만들어지거나 바뀔 때마다 원본을 한 줄씩 덧붙이는 **보존 기록**(`var/ledger.jsonl`, `app/ledger.py`)을 둡니다.

| 요구 | 구현 |
| --- | --- |
| 서버 기준 타임스탬프 | 시각(`ts`)은 요청을 받은 서버의 시계로만 찍습니다(시간대 포함, 초 단위). 브라우저가 보낸 시각은 쓰지 않고, 시연용 날짜 고정(`BOKBOK_TODAY`)과도 무관합니다. |
| 수정/삭제 불가 로그 구조 | `ledger` 모듈에는 덧붙이기(`append`)와 읽기만 있습니다. 같은 날 감정 기록을 고치면 앞의 기록은 남고 새 줄이 생깁니다. 학생이 대화를 화면에서 지우거나 ‘시연 데이터 초기화’를 해도 ‘지웠다/초기화했다’는 줄만 덧붙습니다. |
| 원본 보존 및 해시 기록 | 줄마다 원본(`payload`), 원본의 SHA-256 해시(`payload_hash`), 바로 앞줄의 해시(`prev`), 그리고 순번·시각·종류·대상·원본 해시·앞줄 해시를 묶은 해시(`hash`)를 남깁니다. 한 글자가 바뀌거나, 줄이 빠지거나, 순서가 바뀌거나, 뒤쪽이 잘려 나가면 `ledger.verify()`가 찾아냅니다. |

- **남기는 것**: 감정 기록(감정·강도·단어·문장·공개 여부), 문장 공개 범위 변경, 복복이 대화(학생의 말과 복복이의 대답), 대화를 화면에서 지운 일, 위험 신호 알림과 단계 변경, 선생님의 알림 확인과 사후 관리 기록, 시연 데이터 초기화.
- **확인하는 곳**: 선생님 화면 ‘기록 보존’(`/teacher/ledger`)에서 전체를 다시 계산한 결과와 최근 내역을 봅니다. 원본 내용은 이 화면에 보여 주지 않고 해시만 보여 줍니다. 터미널에서는 `python scripts/verify_ledger.py`(정상 0, 이상 1로 종료).
- **한계**: 해시 연결은 ‘바뀌면 드러나게’ 하는 장치입니다. 서버 관리자가 파일 전체를 새로 만들어 내는 것까지 막으려면 화면의 ‘마지막 해시’를 학교 밖에 주기적으로 맡기는 절차가 함께 필요합니다. 처음부터 들어 있는 합성 데이터와 상담 예약·상점 내역은 보존 기록에 넣지 않았습니다.
- **학생에게 알리는 것**: ‘대화 기록’ 화면의 지우기는 ‘내 화면에서 지우기’이며, 원본은 서버에 보존된다고 화면에 적어 두었습니다.

## 학생 상태를 나누는 기준

`app/analysis.py`의 `day_kind`, `teacher_report`가 계산하고, 기준값은 `data/signals.json`의 `rules`에 있습니다.
숫자는 연구로 검증한 값이 아니라 **현직 교사와 조정해 갈 초기값**입니다.

**1단계 · 하루 기록 나누기** (고른 감정과 강도)

| 고른 감정 | 강도 1~2 | 강도 3 | 강도 4~5 |
| --- | --- | --- | --- |
| 기쁨, 평온 | 좋은 날 | 좋은 날 | 좋은 날 |
| 슬픔, 불안, 분노 | 보통 날 | 힘든 날 | 많이 힘든 날 |

강도가 없는 예전 기록은 3(보통)으로 봅니다. 그래프와 ‘평소보다 하락’ 계산에 쓰는 마음 점수도 보통 날은 가운데 점수(3.0)로 계산합니다.

**2단계 · 최근 7일로 학생 상태 정하기** (하나만 해당해도 그 단계)

| 기준 | 관찰 필요 (주의) | 상담 권장 (심각) |
| --- | --- | --- |
| 많이 힘든 날 | 2일 | 3일 이상 |
| 힘든 날 + 많이 힘든 날 | 4~5일 | 6일 이상 |
| 같은 부정 감정으로 힘든 날이 연속 | 3~4일 | 5일 이상 |
| 평소(지난 한 달)보다 마음 점수 하락 | 0.8 이상 | 1.4 이상 |
| 2주 기록의 절반 이상이 같은 부정 감정으로 힘든 날 | 해당 | — |
| 복복이 대화 신호 | 살펴보기 | 확인 필요, 긴급 |
| 감정 기록 문장의 위험 표현 | — | 해당 |

- 하나도 해당하지 않으면 **안정 (양호)**, 최근 2주 기록이 5건 미만이면 **기록 부족**(상담 권장 기준에 걸리면 그쪽이 우선)입니다.
- 하루만 ‘분노 5’를 골라도 단계는 올라가지 않습니다. 학생이 직접 한 말에서 나온 신호만 바로 반영합니다.

## 팀에서 채워 주실 부분

- `data/help.json`: ‘도움이 필요할 때’ 각 항목의 상황 설명·사례·대처 방법·지원기관. 개발 중에 쓴 초안이라 **팀에서 공식 자료와 맞는지 확인이 필요**합니다. 확인한 항목은 `reviewed`를 `true`로 바꿔 표시해 주세요.
- `data/signals.json`의 `response_guide`: 선생님께 보여 주는 단계별 대응 안내 초안. 현직 교사·상담교사의 검토가 필요합니다.
- `data/chatbot.json`: 복복이의 말투(`system_prompt`, `examples`), 규칙 기반 대답, 안전 안내 문구.
- 서비스 이름은 `app/models.py`의 `SERVICE_NAME` 하나만 바꾸면 됩니다.
